# GitPay server

`@gitpay/server` provides the Phase 0 foundation, Phase 1 draft workflow, Phase 2 authenticated cancellation, Phase 3 sandbox funding, Phase 4 encrypted contributor connections and the local Phase 5 submission/verifier pipeline. [Setup](../../docs/setup.md) covers installation, local Postgres, configuration and provider probes. Phase 4/5 evidence distinguishes automated local checks from missing browser/provider acceptance.

- `src/env.ts` validates explicit configuration; `src/log.ts` redacts secrets.
- `src/main.ts` owns startup/shutdown; `src/http/routes.ts` exposes `GET /healthz` and signed raw-body `POST /webhooks/github`.
- `src/domain/types.ts` defines integer cents, stable IDs and shared action contracts.
- `src/db/` owns the pool, transaction type, Drizzle schema and versioned migrations. Tables include deliveries, jobs, installations, bounties, activity, OAuth states, encrypted sessions and durable Copilot sponsor grants, hashed action tokens and historical funding attempts.
- `src/models/copilot.ts` owns isolated Copilot SDK requests with explicit sponsor credentials/model, denied tools, bounded lifecycle and validated structured output. `src/verifier/` collects bounded exact-SHA evidence, normalizes CI, persists evidence/verdict attempts, and publishes neutral advisory Check Runs; it never pays or selects an award. `scripts/eval-verifier.ts` validates redacted run observations against the six fixed evaluation fixtures. It does not run a live model itself because the SDK adapter exposes no provider cost/token totals.
- `src/preflight/` and `src/paypal/client.ts` implement isolated feasibility probes. Probe identity lives in ignored `.data/preflight/`, not product payment tables. These are not a production settlement service.
- `scripts/` provides migration/preflight entrypoints. `test/helpers/` owns synthetic configuration, network denial and unique-schema test fixtures; `test/unit/` and `test/integration/` hold behavioral coverage.

`src/github/` owns parsing, current access checks and serialized App-owned comments; badge operations live in `app.ts`. `src/jobs/` owns leased execution with heartbeat/fencing. `src/actions/` owns draft creation, status, cancellation guards, contributor connection and submission linking. `src/github/oauth.ts` owns browser-bound login and the separately consented, encrypted, renewable repository-owner Copilot sponsor grant. `src/http/{auth,session,confirm,api,sponsor,connect,retry}.ts` owns cookies, CSRF, sponsor onboarding, payout connection, verification retries, escaped confirmation pages and scoped status reads. `src/util/crypto.ts` owns cryptographic primitives. `src/worker.ts` is the separate worker entrypoint. `domain/funded-terms.ts` creates Copilot v3 terms with sponsor identity and fixed model, retains Copilot v2 and reads legacy Nemotron v1 terms without changing their hashes; `actions/fund.ts` consumes confirmation into a saved intent; `http/fund.ts` owns sponsor/model eligibility checks, review, checkout and read-only return/cancel views. `paypal/orders.ts` normalizes bounded sandbox REST responses, `paypal/webhooks.ts` verifies raw events before enqueueing reads, and `settlement/funding.ts` owns capture reservations, observation fencing and durable due-time reconciliation.

Phase 4 adds encrypted, identity-bound payout connection state and revision-scoped claim-resume jobs; `settlement/claims.ts` is deliberately inert until Phase 6 adds authoritative award records. Phase 5 adds open PR links, immutable evidence, and informational reviews. Organization Copilot sponsorship, usage budgets, actual provider accounting, live fixed-model inference, model evaluation and browser walkthrough remain incomplete. Later phases add awards, payouts and reviewed refunds. Business actions own state transitions; transports delegate to them and external calls stay outside transactions. Update [AGENTS.md](../../AGENTS.md) and the plan target layout when adding modules.

GitHub/PayPal probes use `parsePreflightEnv`; explicit Copilot listing/generation uses `parseCopilotEnv`. Normal preflight does not contact Copilot. HTTP and worker startup use `parseFundingEnv` for GitHub/database/session and funding settings. Full `parseEnv` remains strict for later capabilities; see [ADR 0005](../../docs/decisions/0005-copilot-verifier.md).
