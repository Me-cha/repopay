# Repopay server

Render execution follow-up: durable dispatch, bounded admission, authenticated broker, dedicated/Render executors and independent Check publication are locally implemented, default off. Hosted smoke and cost/latency adoption remain pending. See [runbook](../../docs/review-execution.md) and [evidence](../../docs/evidence/render-workflows-implementation.md). Historical phase gates are unchanged.

`@repopay/server` provides the Phase 0 foundation, Phase 1 draft workflow, Phase 2 authenticated cancellation, Phase 3 sandbox funding, Phase 4 encrypted contributor connections and the local Phase 5 submission/verifier pipeline. [Setup](../../docs/setup.md) covers installation, local Postgres, configuration and provider probes. Phase 4/5 evidence distinguishes automated local checks from missing browser/provider acceptance.

- `src/env.ts` validates explicit configuration; `src/log.ts` redacts secrets.
- `src/main.ts` owns startup/shutdown; `src/http/routes.ts` exposes `GET /healthz` and signed raw-body `POST /webhooks/github`.
- `src/domain/types.ts` defines integer cents, stable IDs and shared action contracts.
- `src/db/` owns the pool, transaction type, Drizzle schema and versioned migrations. Tables include deliveries, jobs, installations, bounties, activity, OAuth states, encrypted sessions and durable Copilot sponsor grants, hashed action tokens and historical funding attempts.
- `src/models/copilot.ts` owns isolated Copilot SDK requests with explicit sponsor credentials/model, denied tools, bounded lifecycle and validated structured output. `src/verifier/` collects bounded exact-SHA evidence, normalizes CI, persists evidence/verdict attempts, and publishes neutral advisory Check Runs; it never pays or selects an award. `scripts/eval-verifier.ts` validates redacted run observations against the six fixed evaluation fixtures. By default it makes no provider calls. Its opt-in live mode delegates to `verifier/evaluate.ts`, uses a current stored repository-owner sponsor, makes at most 18 requests and checkpoints redacted observations; Auto reports require actual serving-model IDs.
- `src/preflight/` and `src/paypal/client.ts` implement isolated feasibility probes. Probe identity lives in ignored `.data/preflight/`, not product payment tables. These are not a production settlement service.
- `scripts/` provides migration/preflight entrypoints. `test/helpers/` owns synthetic configuration, network denial and unique-schema test fixtures; `test/unit/` and `test/integration/` hold behavioral coverage.

`src/github/` owns signed authorization-revocation handling, parsing, current access checks and serialized App-owned comments; badge operations live in `app.ts`. `src/jobs/` owns leased execution with heartbeat/fencing. `src/actions/` owns draft creation, status, cancellation guards, contributor connection and submission linking. `src/github/oauth.ts` owns browser-bound login and the separately consented, encrypted, renewable repository-owner Copilot sponsor grant. `src/http/{auth,session,confirm,api,sponsor,connect,retry}.ts` owns cookies, CSRF, sponsor onboarding, payout connection, verification retries, escaped confirmation pages and scoped status reads. `src/util/crypto.ts` owns cryptographic primitives. `src/worker.ts` is the separate worker entrypoint. `domain/funded-terms.ts` creates Copilot v4 terms with sponsor identity and Auto (v5 only for scoped cancellation), and reads legacy terms without changing their hashes; `actions/fund.ts` consumes confirmation into a saved intent; `http/fund.ts` owns sponsor/model eligibility checks, review, checkout and read-only return/cancel views. `paypal/orders.ts` normalizes bounded sandbox REST responses, `paypal/webhooks.ts` verifies raw events before enqueueing reads, and `settlement/funding.ts` owns capture reservations, observation fencing and durable due-time reconciliation.

Phase 4 adds encrypted, identity-bound payout connection state and revision-scoped claim-resume jobs; `settlement/claims.ts` validates resume events before Phase 6 resumes the existing authoritative award. Phase 5 adds open PR links, immutable evidence, and informational reviews. Organization Copilot sponsorship, usage budgets, actual provider accounting, remaining browser acceptance remain incomplete; Auto v2 evaluation passed 18/18. `src/policy/` provides deterministic payment policy and exact-cent allocation. Phase 6 adds `settlement/candidates.ts` for bounded REST/GraphQL candidate scans, `settle.ts` for immutable evidence-bound awards, `payout.ts` for immutable account-bound intents and fenced item reconciliation, and `service.ts` for worker polling and delayed claims. `paypal/payouts.ts` implements bounded sandbox batch creation/read adapters. Automatic award selection is restricted to the explicit ADR 0008 demo scope. The first $50 payout and recipient receipt are confirmed; delayed-claim/two-author acceptance remains pending. Reviewed refunds are locally implemented but remain disabled pending isolated live acceptance. Business actions own state transitions; transports delegate to them and external calls stay outside transactions. Update [AGENTS.md](../../AGENTS.md) and the plan target layout when adding modules.

GitHub/PayPal probes use `parsePreflightEnv`; explicit Copilot listing/generation uses `parseCopilotEnv`. Normal preflight does not contact Copilot. HTTP and worker startup use `parseFundingEnv` for GitHub/database/session and funding settings. Full `parseEnv` remains strict for later capabilities; see [ADR 0005](../../docs/decisions/0005-copilot-verifier.md).

`settlement/profile.ts` binds optional scoped sandbox settlement to a single bounty/repository/amount/frozen-terms hash and the evaluated Auto prompt/SDK. Empty `SETTLEMENT_DEMO_SCOPE` keeps candidate scheduling disabled. Runtime selection checks current owner sponsorship, rejects revoked grants under the award lock and permits only the evaluated serving model. Changed merged evidence is queued for review before award selection. Existing committed awards continue reconciliation independently of new-award activation. Scope activation requires the documented acceptance decision; it is not general production enablement.

Phase 7 adds `actions/approve.ts`, `actions/reject.ts` and `http/review.ts` for full-amount, reasoned review and revision-bound rejection. `settlement/award.ts` is the shared final award guard. Migration 0013 stores immutable review history. `/bounties/:id/review` prepares an exact split; `/review/:token` confirms it. Approval remains limited to the configured settlement scope. See [Phase 7 evidence](../../docs/evidence/07-summary.md).

Phase 8 adds `cancellation/{authorization,evidence,service,runtime}.ts`, `http/cancellation.ts`, `settlement/refund.ts` and `paypal/refunds.ts`. Migration 0014 stores notice deadlines, append-only claim snapshots/decisions and immutable refund identities. Version 5 terms disclose cancellation only for explicitly scoped new funding; versions 1–4 remain unchanged. Worker polling collects objections and reconciles committed refunds; browser actions cannot choose another capture/destination. See [Phase 8 evidence](../../docs/evidence/08-summary.md), [ADR 0010](../../docs/decisions/0010-cancellation-refund-boundaries.md) and [operations](../../docs/operations.md).

Phase 9 adds `read-models/{contracts,bounties,payouts}.ts` for whitelisted scoped API data, `http/dashboard.ts` for same-origin built assets and `http/sse.ts` for reauthorized invalidation hints. Migration 0015 publishes transactional activity wakeups. One shared listener serves browser connections; heartbeat refetch repairs missed/out-of-order IDs. Test-only login/provider seams are under `test/e2e/fixture-server.ts`, excluded from production source. See [ADR 0011](../../docs/decisions/0011-scoped-dashboard.md).

Phase 10 adds `jobs/scheduler.ts`, `github/reconciliation.ts`, `operations/attention.ts`, `scripts/retry-job.ts` and migration 0016. Checkpoints commit with durable work; discovery is not award eligibility evidence. Known financial polling continues despite failure in another subsystem. `pnpm ops:retry-job <id>` only retries allowlisted read/projection work with preserved failed records. [ADR 0012](../../docs/decisions/0012-recovery-checkpoints.md) describes bounds and default-off discovery activation. Restart/fault helpers remain test-only.

Phase 11 adds `db/compatibility.ts` and `scripts/check-migrations.ts`. Startup and readiness reject mismatched migration history. `RECOVERY_MODE=hold` blocks all worker polling/claims and HTTP mutations before restoring data; it does not infer missing provider effects from restored SQL. The prepared Render topology uses separate built web/worker services, with migrations only in the web pre-deploy step. See [deployment](../../docs/deployment.md).

Phase 12 adds `scripts/demo-seed.ts`, an independent dry-run-first GitHub CLI helper for ordinary preparation issues in the exact detached demo repository. It does not import server configuration, connect to the application database, create bounties or initiate transfers. See [demo instructions](../../docs/demo.md) and [final acceptance](../../docs/evidence/12-acceptance.md).

`github/app.ts:fileAtRevision` supplies blob-verified UTF-8 test content at an immutable head SHA. `verifier/collect.ts` appends at most four changed-test files as untrusted context within the existing funded diff budget and repeats the head/base check afterward. Missing access or incomplete context holds the review. See [ADR 0014](../../docs/decisions/0014-exact-revision-test-context.md).

Pre-merge rejection: `candidateScanner` collects the explicitly targeted PR alongside merged candidates; `actions/approve.ts` stores revision-bound decisions without requiring that target to merge. `http/review.ts` is approval-only. Migration 0017 permits nullable merge SHA only for rejection and preserves deduplication; see ADR 0015.

Verifier context now includes up to four changed source files alongside up to four changed test files under shared frozen/runtime limits. Prompt v3 requires fresh acceptance; `settlement/profile.ts` intentionally retains evaluated v2 and blocks new v3 awards. See ADR 0016. No migration or environment change.

Contributor attribution: `actions/attribution.ts` owns immutable head/base-bound declarations and distinct maintainer confirmations; `http/attribution.ts` exposes `/submissions/:id/contributors`. Migration 0018 is required. Both the verifier and final candidate scan read confirmed authors. No model request or payment is triggered by confirmation. See [ADR 0017](../../docs/decisions/0017-confirmed-contributor-attribution.md).

GitHub next-action discovery: `github/comments.ts` projects issue setup/status, PR review and contribution commands, and winning-PR allocations/connection links. Durable `sync_submission` jobs retry projection without another model call. `actions/attribution.ts` shares revision/award fencing between browser confirmations and signed PR commands; see [ADR 0018](../../docs/decisions/0018-github-contributor-commands.md).

`actions/retry.ts` authorizes and coalesces signed PR-comment review requests; `actions/cancel.ts` shares unfunded cancellation guards with the issue-command transport. The verifier stores bounded GitHub commit/attestation context inside the existing immutable evidence snapshot. Prompt v5 adds semantic counterexample guidance after v4 failed; full live evaluation is deferred; ADR 0021 permits only default-off exact-bounty foundation sandbox scopes with the existing settlement guards. See [ADR 0020](../../docs/decisions/0020-verifier-semantic-counterexamples.md). See [ADR 0019](../../docs/decisions/0019-review-evidence-and-pr-retry.md).

Dashboard onboarding: `actions/onboarding.ts` atomically inserts one `user_onboarding` row per authenticated GitHub ID; `http/onboarding.ts` supplies path-bound CSRF and GET/POST `/api/onboarding/dashboard`. Migration 0020 is required. It stores no payout/profile data and does not enqueue financial work.
