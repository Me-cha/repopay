# ADR 0019: Contribution evidence and PR-native review retry

Date: October 31, 2026. Status: user-approved implementation; locally implemented and verified, deployment/live acceptance pending.

The hosted PR #12 review returned PARTIAL solely because its input omitted evidence of contributor declarations and maintainer confirmation. The collector already used these records to determine eligible identities, but the model received only IDs/logins. Do not override that verdict or alter funded criteria to erase the missing evidence.

The collector now includes a JSON contribution-evidence block in the existing immutable `diff_text` snapshot, alongside full-file context. It records exact head/base, authenticated PR identity, GitHub-associated commit SHAs, pagination completeness, immutable claimant/maintainer record IDs, actor IDs, reasons and timestamps. Only current-revision records are included. Commit associations do not establish cryptographic authorship, and reasons remain untrusted user assertions; code correctness and actual contribution still require evidence. No emails, credentials or raw webhook bodies are included. At most 100 associated commit records and 32 attestation records fit within the existing shared diff/context budget; exceeding either cap or the remaining budget makes evidence incomplete. The block is included in the snapshot hash and persisted before inference; no database migration is needed.

This changes the verifier contract to `gitpay-verifier-v4`. Historical v3 acceptance remains historical. The exact-bounty settlement profile stays pinned to evaluated v3, so v4 cannot authorize new awards until separately evaluated and accepted. Existing committed awards remain deliverable. Local payload tests do not establish semantic model performance; v4 needs bounded live evaluation, including the two-contributor evidence case. No further model allowance is implied.

Primary work actions stay in GitHub. `/bounty retry [#issue] [<head SHA> <base SHA>]` on an open PR requires current write permission, the current installation and eligible funded scope, and no committed award/funding hold. Supplied revision bindings must match. The bot publishes a full revision-bound command; the short command selects the current revision at execution. Ambiguous bounty links require an issue number. A transactional lease and bounty/submission locks protect enqueueing; concurrent active requests coalesce, and durable per-command activity prevents acknowledgement retries from submitting again. A requested verification job has one execution attempt; uncertain outcomes require explicit recovery instead of silently spending another request. Existing per-repository/day/revision inference caps remain enforced by the verifier. This is a request count control, not a monetary guarantee.

`/bounty status [#issue]` also works on the PR and refreshes its canonical bot summary. Declarations, independent confirmations, rejection and ordinary maintainer feedback remain PR-native. `/bounty cancel` on the issue now cancels only an unfunded draft directly after signed-actor write authorization and the same transactional capture/state guards; it cannot refund a funded bounty. This supersedes the browser-confirmation requirement for unfunded draft cancellation. Historical evidence remains intact.

Bot review/check instructions no longer route fresh-review requests to GitPay. Funding, account/sponsor consent and financial award/payout confirmations remain authenticated web flows. Existing bookmarked authenticated pages remain compatible fallbacks, and the optional dashboard remains read-only; neither is required for these non-financial work actions. The separately deferred funded-refund/operator workflow remains disabled and retains its financial authorization boundaries.
