### 05.03 — Run a bounded structured-output verifier

**Files:** `packages/server/src/verifier/schema.ts`, `packages/server/src/verifier/prompt.ts`, `packages/server/src/verifier/verify.ts`, `packages/server/src/db/migrations/0007_phase4_5.sql`, `packages/server/test/unit/verifier.test.ts`.

**Depends on:** 05.02 and phase prerequisites.

**Interface and implementation contract:** verify(input: VerifyInput): Promise<VerifierResult>. Verdict is RESOLVES | PARTIAL | DOES_NOT_RESOLVE, with coverage/confidence in [0,1], reasoning, unmetRequirements and proposed shares keyed by server-provided stable author IDs. Zod rejects invalid/unknown authors, nonfinite numbers and malformed output. Store model/prompt hash/attempt, SDK/profile version, sponsor identity and evidence sufficiency. Reuse `models/copilot.ts` for one isolated, tool-free structured-output call with the funded model; errors remain explicit and valid negative verdicts are final. Live Copilot/schema compatibility and semantic quality are not established by the historical Nemotron probe. Version 1 funded terms must not silently switch to Copilot.

**Sponsor onboarding prerequisite:** the personal repository-owner path is implemented in `http/sponsor.ts`, `github/oauth.ts`, and `copilot_sponsors` storage. It uses separate OAuth consent, validates owner identity and the accepted model profile, encrypts/refreshes the grant independently of the browser session, and binds sponsor/Auto into v4 funding terms, retaining legacy v1–v3 terms. The adapter captures SDK token, nano-AIU and premium-request metrics; successful attempts persist usage with their verification record. Configurable UTC-day repository and per-SHA attempt caps are implemented. These limit GitPay requests but do not guarantee a monetary ceiling; GitHub account/org billing controls remain authoritative. Organization installation billing and accepted live Auto evaluation remain open. Signed user-authorization revocation invalidates grants/sessions, refresh is generation-fenced, and reviews recheck sponsor availability after inference. The local adapter's `COPILOT_BILLING_OWNER_ID` is probe metadata, not the customer authorization mechanism.

- [ ] Pin the following acceptance cases in the named test file(s), or in the explicit manual evidence record for external/tooling-only checks: prompt_injection_has_no_tools_for_money; malformed_result_not_payable; timeout_records_error; impossible_share_rejected; unsupported_model_parameter_not_sent. Large/truncated inputs and insufficient evidence are review cases even if the model emits confidence 1. Do not execute contributor code in the API/worker.
- [x] Implement strict schema validation, injection-aware prompt construction and a tool-free, funded-profile call bound to sponsor terms. Live provider compatibility remains unverified.
- [x] Run verifier unit tests and the full suite; see [Phase 5 evidence](../evidence/05-summary.md).
