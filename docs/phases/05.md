### 05.03 — Run a bounded structured-output verifier

**Files:** `packages/server/src/verifier/schema.ts`, `packages/server/src/verifier/prompt.ts`, `packages/server/src/verifier/verify.ts`, `packages/server/src/db/migrations/0007_verifications.sql`, `packages/server/test/unit/verifier.test.ts`.

**Depends on:** 05.02 and phase prerequisites.

**Interface and implementation contract:** verify(input: VerifyInput): Promise<VerifierResult>. Verdict is RESOLVES | PARTIAL | DOES_NOT_RESOLVE, with coverage/confidence in [0,1], reasoning, unmetRequirements and proposed shares keyed by server-provided stable author IDs. Zod rejects invalid/unknown authors, nonfinite numbers and malformed output. Store model/prompt hash/attempt, capability-profile version and evidence sufficiency; one bounded retry, then explicit error. Verify tool parameters against the selected model in Phase 00 and send only supported parameters.

Large/truncated inputs and insufficient evidence are review cases even if the model emits confidence 1. Do not execute contributor code in the API/worker.

## End-to-end walkthrough

Two contributors open competing PRs on the same funded issue. Show both checks, push a new commit, retry a failed assessment, and run the fake-fix/injection fixtures. No PR is exclusively assigned and no payment occurs before a qualifying merge.
