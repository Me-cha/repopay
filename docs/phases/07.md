# Phase 07: Maintainer review and submission decisions

> **For agentic workers:** Implement task-by-task when authorized, following repository AGENTS.md and the contracts below. Optional skills are not prerequisites; do not assume uninstalled skills exist. This plan does not authorize execution.

**Status:** Draft for review · implementation not started.

**Goal:** A maintainer can resolve an uncertain merged submission without bypassing financial or recipient guards.

**Architecture:** GitHub-first workflows; authoritative Postgres state and durable jobs; authenticated financial actions; external calls outside transactions. Reuse the approved domain and provider boundaries instead of introducing parallel state machines.

**Tech stack:** TypeScript strict, Node 22, pnpm, Express, PostgreSQL 16/Drizzle, Zod, Vitest; Octokit/PayPal/Anthropic and web tooling only where this phase needs them.

**Spec:** [Implementation plan](../../IMPLEMENTATION_PLAN.md), [cancellation decision](../decisions/0001-open-participation-and-cancellation.md), and [MVP review index](README.md).

**Prerequisites:** [Phase 06](06.md)

**Scope:** Review summaries, full-amount approval, rejection/reconsideration and explicit stale-evidence handling. Partial awards and direct refunds remain outside this phase.

## Global constraints

Follow the shared [execution contract](README.md#execution-contract) and [review focus](README.md#review-focus). Open participation, persistent awards, independently reviewed exceptions, exact cents and sandbox-only money are mandatory. All listed code paths are planned unless already present when implementation begins. Preserve unrelated work.

### 07.01 — Present an exact review decision

**Files:** `packages/server/src/actions/approve.ts`, `packages/server/src/http/confirm.ts`, `packages/server/src/github/comments.ts`, `packages/server/test/integration/review-preview.test.ts`.

**Depends on:** Phase prerequisites and shared types from Phase 00.

**Interface and implementation contract:** issueApproveToken(ctx:ActorContext,bountyId:string): Promise<ActionResult<string>>. Preview stored candidate, merged revision, current CI/verifier reasons, full amount and eligible recipient split. If AI attribution is unusable, allow choosing a single verified eligible author; never free-text payment destinations.

**Review completion contract:** Recipient selection creates a new bound preview/token; final confirmation cannot substitute an allocation. Test changing selected recipient after preview and a token whose underlying evidence changed.

## End-to-end walkthrough

Merge a partial solution, inspect NEEDS_REVIEW, approve the full amount with reason, then demonstrate a separate rejection that moves consideration to another merged PR. Show stale-token rejection after new evidence.
