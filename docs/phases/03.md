# Phase 03: Funding and authoritative capture

> **For agentic workers:** Implement task-by-task when authorized, following repository AGENTS.md and the contracts below. Optional skills are not prerequisites; do not assume uninstalled skills exist. This plan does not authorize execution.

**Status:** Authorized October 28, 2026 · local implementation reviewed; real sandbox capture gate pending. The user deferred Phase 02’s live revoked-write check; automated coverage remains mandatory.

**Goal:** A maintainer can fund a bounty through PayPal sandbox and see confirmed captured funds in GitHub.

**Architecture:** GitHub-first workflows; authoritative Postgres state and durable jobs; authenticated financial actions; external calls outside transactions. Reuse the approved domain and provider boundaries instead of introducing parallel state machines.

**Tech stack:** TypeScript strict, Node 22, pnpm, Express, PostgreSQL 16/Drizzle, Zod, Vitest; GitHub/PayPal/Copilot SDK and web tooling only where this phase needs them.

**Scope:** Orders, checkout, immutable funded terms, capture, verified PayPal events and reconciliation. Refund transport may be prepared later; funded cancellation stays disabled.

**Depends on:** 03.03 and phase prerequisites.

**Interface and implementation contract:** ingestPayPal(rawBody: Buffer,headers: PayPalHeaders): Promise<DeliveryResult>. Preserve exact raw bytes, parse untrusted input for PayPal signature verification, require SUCCESS before durable business processing and bound signature-verification calls; no capture/payout fan-out in the handler.
