# Phase 09: Read-only visibility and complete user journeys

> **For agentic workers:** Implement task-by-task when authorized, following repository AGENTS.md and the contracts below. Optional skills are not prerequisites; do not assume uninstalled skills exist. This plan does not authorize execution.

**Status:** Local implementation and automated verification complete (2026-10-30). Live role/provider walkthroughs are deferred by user direction; full phase acceptance remains open. See [local evidence](../evidence/09-summary.md) and [final live checklist](live-walkthroughs.md).

**Goal:** Maintainers, contributors and operators can understand current progress, money state and next actions without introducing a second management platform.

**Architecture:** GitHub-first workflows; authoritative Postgres state and durable jobs; authenticated financial actions; external calls outside transactions. Reuse the approved domain and provider boundaries instead of introducing parallel state machines.

**Tech stack:** TypeScript strict, Node 22, pnpm, Express, PostgreSQL 16/Drizzle, Zod, Vitest; GitHub/PayPal/Copilot SDK and web tooling only where this phase needs them.

**Spec:** [Implementation plan](../../IMPLEMENTATION_PLAN.md), [cancellation decision](../decisions/0001-open-participation-and-cancellation.md), and [MVP review index](README.md).

**Prerequisites:** [Phase 08](08.md)

**Scope:** Scoped read APIs, a minimal dashboard, live updates and accessible confirmation/connect pages. Charts, natural-language filtering, pivoting and AG Studio are post-MVP and are not created by this phase.

### 09.03 — Deliver scoped live updates and reconnect safely

**Files:** `packages/server/src/http/sse.ts`, `packages/web/src/api.ts`, `packages/server/test/integration/sse.test.ts`, `packages/web/test/live-updates.test.ts`.

**Depends on:** 09.02 and phase prerequisites.

**Interface and implementation contract:** GET /api/stream emits scoped `bounty_activity.id` cursors and public invalidation hints. The server wakes subscribers through PostgreSQL LISTEN/NOTIFY but treats the activity table as the durable cursor. Reauthenticate scope on reconnect and periodic permission refresh; revoke streams on lost access/session expiry. Handle missed IDs with full scoped refetch, not assumptions that all events arrived.

**Review completion contract:** Activity sequence IDs are not transaction commit order. Treat SSE as invalidation hints; run a periodic scoped full refetch using the configured heartbeat cadence, including reconnect and tab focus. Test lower ID committing after a higher ID has been delivered. Authorization refresh must fail closed; retain no stale private cache after access loss.

- [x] Pin the following acceptance cases in the named test file(s), or in the explicit manual evidence record for external/tooling-only checks: private_repo_event_not_leaked; expired_session_stream_closed; disconnect_reconnect_correct_state; duplicate_event_idempotent_render; separate_worker_notification_refetch. Financial actions never depend on the browser receiving an event.
