# Phase 08: Exceptional cancellation and guarded refunds

> **For agentic workers:** Implement task-by-task with the executing-plans or subagent-driven-development skill when implementation is authorized. Follow repository AGENTS.md; this review draft does not authorize execution.

**Status:** Draft for review · implementation not started.

**Goal:** Genuine cancellation requests can receive reviewed refunds without enabling cancel-then-merge abuse or exclusive contributor claims.

**Architecture:** GitHub-first workflows; authoritative Postgres state and durable jobs; authenticated financial actions; external calls outside transactions. Reuse the approved domain and provider boundaries instead of introducing parallel state machines.

**Tech stack:** TypeScript strict, Node 22, pnpm, Express, PostgreSQL 16/Drizzle, Zod, Vitest; Octokit/PayPal/Anthropic and web tooling only where this phase needs them.

**Spec:** [Implementation plan](../../IMPLEMENTATION_PLAN.md), [cancellation decision](../decisions/0001-open-participation-and-cancellation.md), and [MVP review index](README.md).

**Prerequisites:** [Phase 07](07.md)

**Scope:** Notice, evidence and objections, independent operator access, decisions, refund reservation/submission/reconciliation and protection of valid submissions. This phase gates FUNDED_CANCELLATION_ENABLED.

### 08.04 — Reserve refunds with a precise unsent/in-flight boundary

**Files:** `packages/server/src/settlement/refund.ts`, `packages/server/src/actions/guards.ts`, `packages/server/src/db/migrations/0011_refund_intents.sql`, `packages/server/test/integration/refund-authorization.test.ts`.

**Depends on:** 08.03 and phase prerequisites.

**Interface and implementation contract:** authorizeRefund(requestId:string): Promise<ActionResult<RefundIntent>>. Refresh live evidence outside transaction; under lock validate matching versions, notice, authorized reviewer, no unresolved qualifying claim/award and full captured principal. Store the cancellation request as APPROVED, create a `RESERVED` refund intent, and transition it to `MAY_HAVE_SUBMITTED` at the durable submission boundary before the external call. Intent states: RESERVED, ABORTED_UNSENT, MAY_HAVE_SUBMITTED, IN_FLIGHT, SETTLED_OK, SETTLED_FAIL. Permit historical attempts per request with at most one active intent.

Stale reviewers and loss of access prevent first submission. Re-approved evidence requires a new audited intent; never overwrite an old uncertain one. An uncertain intent remains reserved until provider reconciliation.
