### 02.03 — Render and consume confirmation tokens

**Files:** `packages/server/src/http/confirm.ts`, `packages/server/src/actions/tokens.ts`, `packages/server/src/db/migrations/0003_action_tokens.sql`, `packages/server/test/integration/confirm.test.ts`.

**Depends on:** 02.02 and phase prerequisites.

**Interface and implementation contract:** issueActionToken(input: ActionTokenInput): Promise<string>; confirmAction(ctx: ActorContext,token: string,csrf: string): Promise<Bounty>. Store only token hash; bind action, params, bounty version and expiry. GET previews never mutate action state; login/callback GETs maintain the OAuth handshake. A CSRF-protected POST to the stable preview route prepares the token. Action failures throw typed safe errors through the transaction boundary to guarantee rollback. POST validates Origin/CSRF and consumes token atomically with the action.

**Review completion contract:** A page-selected eligible recipient must be validated and bound to a freshly issued token/preview before final confirmation; never accept a modified allocation from POST. Apply no-store and no-referrer to sensitive pages, redact action-token URLs in access logs and enforce CSRF/Origin on connect/logout too.
